# 照東國小公文承辦流程

承辦人：教導處 王佩霆（教導主任）。校長：齊宗豫。訓導組長：林郡慧。人事：黃信諺。資訊聯絡人：彭成德。
教導處內會順會人員名單：張唯娟、彭成德、林郡慧、劉琬鎔。

**核心工作模式**：為了兼顧效率與把關，AI 自動完成每件公文的全部流程（判斷、擬辦、流程設定、核章），但**絕不按最終對外發文的「送出」**。全部處理完後由使用者逐件做最終檢查、親手送出。因此中途不需徵求使用者同意，直接連續處理到所有公文完成為止。

**瀏覽器連線提醒**：若 Claude in Chrome 偵測到帳號連接了多個瀏覽器，開始操作前務必先確認要用哪一個（依工具指示列出所有已連線瀏覽器讓使用者選，不可自行預設），確保使用者看得到畫面在動。

## 一、登入公文管理系統

1. 用 Claude in Chrome 開啟 https://hchg.cloudop.tw/HCHGOP/
2. 點「自然人憑證登入」頁籤
3. 機關下拉選「新竹縣新埔鎮照東國民小學」（關鍵字可輸入「照東」）
4. 密碼（自然人憑證PIN碼）必須由使用者親自輸入。若瀏覽器已自動帶入，直接按「登入」。
5. 登入後進儀表板，回報待處理件數。

## 二、建立待辦清單（先列清單、標記未處理，不要先逐件讀取檢查——避免浪費時間）

**開始處理前，只做這一步，不要先把每件公文內容都讀一遍去判斷是否已處理：**

1. 進「承辦人作業 → 主辦公文」，讀取清單頁面上**全部**文號、主旨，列成一份完整待辦清單（用 TaskCreate 每個文號建一個任務，或至少在回報中列出完整文號列表），並記下清單總筆數。
2. 清單上每一個文號，一律先標記為「未處理」（狀態 pending）。**不要為了確認要不要跳過，先花時間逐件打開檢查內容**——直接假設全部未處理，進入第三節依序處理即可。
3. 只有在單一文號實際處理的當下（開啟該件、走到第四節）才需要判斷「是否已有擬辦單內容」（見第四節「先檢查再新增」），這是處理該件當下的一個步驟，不是處理前的預先檢查階段。
4. 每處理完一件、且第三～六節的判斷、擬辦、流程、核章都已確認存在，才把該文號從「未處理」改成「已處理」（TaskUpdate 設 completed）。
5. 全部文號都變成「已處理」才算完成本輪任務；中途不可跳過任何一件不管其分類為何。
6. **核章成功的文件會直接從「主辦公文」清單消失**（流程往下一關送出，離開本人的主辦清單），這是正常現象，不是文件不見了。每次重新整理清單時，筆數變少屬預期行為。

## 三、開啟公文並判斷重要性（先判斷再動手）

1. 開啟個別公文時，點該列的「主旨」欄（不要點文號）。若 find 點不動，改用座標點該列主旨文字。
2. 進公文製作畫面後，用頁面文字讀取來文全文（主旨＋說明），務必讀完「說明」才判斷。

依標準分類並告知使用者「分類：原因是…」：

- **非常重要**：需本單位回覆／填報／陳核；有強制配額（務必參加、至少派一員、各校依計畫派員）；有明確期限；本校人員須出席。
- **重要**：與本校業務相關、值得知悉，但無強制辦理事項（含校長場活動供校長知悉決定）。
- **不重要**：自由報名研習（無配額）、宣導周知、活動邀請徵詢意願、與本校性質業務無關。

拿不準時依上列標準自行判斷選最接近的一類，不要中斷詢問；判斷依據寫入最後的總表供使用者把關。

**注意：分類只決定擬辦用語與是否需要會辦，不代表可以不處理。即使判斷為「不重要」，仍必須依第四～六節建立擬辦單、填擬辦、設定流程並核章，一件都不能漏。**

## 四、建立公文擬辦單

**先檢查再新增（處理當下才做，不是預先檢查）**：開啟這件公文後，先實際點開「文書清單」確認此件是否已經有擬辦單，且該擬辦單內容確實已填寫（不是空白草稿）。只有在確認擬辦單內容真的存在時，才可跳過本節與第五節、直接從第六節（設定流程與核章）接續。**不可只憑公文列表的狀態文字（如「承辦人簽收」）判斷已處理過**——這個狀態即使擬辦單是空的也可能出現，一定要打開實際內容核對。

1. 按「新增」→ 範本選「公文擬辦單」(T003)
2. 「是否於文面帶入來文說明？」→ 選「是」
3. 點文面下方紅字「第　層決行」→ 決行層級選「第一層決行」→ 確定
4. 檔號/保存年限視窗有**兩個下拉選單**：第一個是承辦單位（教導處，通常已預設），**要設的是第二個「保存年限」下拉**，選「0111/1-5年(綜合業務)」(值 0111,1,5) → 確定

## 五、填擬辦（重要：此編輯器極易跑位與吃字，務必照下列方法）

**擬辦內容由 AI 根據來文內容自行判斷、直接填寫，不需先徵求使用者同意。**（最終把關在送出前由使用者進行，見第七、八節。）

擬辦欄有「一、」「二、」兩個自動編號空行。可靠輸入步驟：

1. 先點「擬辦：」或「一、」附近，再按方向鍵 ↑ 或 ↓ 移到「一、」那一行，再按 End，才開始輸入。**不要直接點空白行打字**（最常跑到二、或會辦單位行）。
2. 輸入後**一定放大檢查**：此編輯器常吃掉第一個字（如「請」變不見、「文存」剩「存」）。若首字被吃，按 Home 回行首補上該字。
3. 若整段跑到錯行（二、／會辦單位／來文說明），用 Backspace 刪乾淨，回到步驟1重來。
4. 填完並存檔後，**務必重新讀取該段落文字（例如查詢頁面上「一、」開頭的段落內容）確認真的存進去了**，不可只憑「按過儲存鍵」就認定已完成。

擬辦用語（不加挪抬空格）：
- 需其辦理／填報事項的組長 →「請○○組長協助辦理。」（用職稱如「教學組長」「訓導組長」，不用姓氏——組長會換人，用姓氏易出錯）
- 需其出席研習／會議 →「請○○組長參加。」（同樣用職稱不用姓氏）
- 給校長知悉／校長場活動 →「請鈞長參閱。」
- 有明確期限需辦理、非特教業務 →「依文辦理。」
- 特教業務（含通報、填寫等）→「請特教業務承辦人協助辦理。」
- 無需辦理、僅歸檔 →「文存。」

判斷會辦對象：兒童權利公約等訓導業務＝訓導組長 林郡慧；敘獎案要會人事 黃信諺；**主旨或說明中出現「含資訊人員」「資訊組長」「資訊業務」等與資訊相關字樣時，一律內會資訊聯絡人 彭成德**（例如主旨為「…第6次教務主任會議（含資訊人員）」這類含資訊人員參與/知會的公文）。對象不明時依公文屬性自行判斷最合理的人選，**不要中斷詢問**（中斷會打斷整個連續處理流程）；不確定的判斷在最後總表中特別註記，由使用者把關時修正。

## 六、設定流程與核章

每件公文都必須有擬辦內容，不可省略。依擬辦內容判斷是否需要「內會順會」或「順會」其他相關人員（例如敘獎會人事、教學業務會教學組長、含資訊人員會資訊聯絡人彭成德等），但無論該件是否需要會辦其他人員，最後都必須加上一道「陳核一層→校長室→齊宗豫」的流程，不可省略陳核校長這一步，即使是單純轉知、依文辦理、文存等看似不需校長批示的公文，也一律陳核校長。

1. 按「流程」開「設定公文流程」：
   - 若需會辦特定組長 → 先「內會順會」→ 教導處 → 該組長 → 加入
   - 若涉及敘獎 → 「順會」→ 人事室 → 黃信諺 → 加入
   - 若主旨/說明提及含資訊人員、資訊業務 → 「內會順會」→ 教導處 → 彭成德 → 加入
   - 不論以上是否有會辦對象，一律再加一筆「陳核一層」→ 校長室 → 齊宗豫 → 加入（會辦在前、校長在後）
   - 流程對話框裡實際的加入/儲存按鈕是 `#btnJoin`（加入）與 `#btnSaveFlow`（儲存），這兩個是 `<input type="button">`，本身沒有文字內容，用 id 選取即可，不要用文字比對找。
   - 下拉選單用 `jQuery('#lstStatusID').val('A00'或'B03').trigger('change')`（A00=陳核一層，B03=內會順會），接著 `jQuery('#lstRcvDepID').val(...).trigger('change')`，再 `jQuery('#lstRcvUserID').val(...).trigger('change')`——每設一個都要等待約1秒讓下一層下拉選單跑出選項，一定要用 jQuery `.trigger('change')`，原生 `dispatchEvent` 不會觸發串聯。
2. 點 `#btnJoin` 加入流程，確認畫面上已出現「陳核一層->校長室->齊宗豫」等設定的字樣，再點 `#btnSaveFlow` 儲存並關閉流程視窗。
3. 點「核章/送出」開啟簽核意見面板（此按鈕實際上是 `<li>` 元素，內含 `<span id="簽核意見">核章/送出</span>`；用 `jQuery(li).trigger('click')` 才能可靠觸發，直接 `.click()` 常常沒反應）。
4. **關鍵：面板裡真正用來核章、記錄簽核意見的按鈕是 `#btnSignSave`（值="核章"），不是 `#btnsend`（值="送出"）！** 這兩個是不同按鈕：
   - `#btnSignSave`（核章）＝記錄本人（承辦）這一關的簽核意見，這是每件公文的標準必要步驟，不必每次都另外詢問使用者確認，直接點即可。點完後畫面會在簽核表格出現一列「單位/職稱/姓名/時間(承辦)」，代表核章真的成功了，務必用這個核對，不能只看「有沒有跳錯誤訊息」。
   - `#btnsend`（送出）＝往下一關送出／推進流程用的按鈕，若在**還沒點 `#btnSignSave` 核章之前**就點了 `#btnsend`，會跳出「公文送出」對話框並顯示「尚有文書未給簽核意見，若無意見請點擊承辦(會辦、核示)按鈕」的錯誤提示——這代表點錯按鈕了，要關閉這個對話框（找 `.close` 按鈕），改點 `#btnSignSave` 才對。
   - 正確順序：先點 `#btnSignSave`（核章，確認簽核表格出現承辦紀錄），核章成功後**不需要**再點 `#btnsend`，直接點工具列的「離開」，會跳出「是否存檔並離開公文製作？」→ 點「是」即可完成並自動離開（該文件會從主辦公文清單消失，往下一關送出）。
5. 若跳「請輸入憑證密碼」，瀏覽器自動帶入則按確定，否則請使用者輸入。
6. 核章（`#btnSignSave` 且簽核表格出現承辦紀錄）成功後才可離開本件。

## 七、不送出，離開換下一件（關鍵：最終把關留給使用者）

1. 若不小心先點了 `#btnsend` 導致跳出「公文送出」對話框（標題含「公文送出」、內容為「尚有文書未給簽核意見」等錯誤提示）→ 這不是最終對外發文，是操作順序錯誤的提示，直接關閉（`.close` 按鈕）即可，接著改用第六節正確順序（先 `#btnSignSave` 核章）重新來過。
2. 真正需要提防、絕對不能按的，是核章、流程都跑完、所有簽核關卡都結束後才可能另外出現的**對外正式發文確認**視窗——但依目前實測，正常流程（核章→離開→是否存檔並離開→是）並不會觸發這個視窗，只要不誤點 `#btnsend`，走「核章→離開→是」這條路徑就是安全的。
3. 確認本件的擬辦、流程、核章都已儲存（簽核表格有承辦紀錄）後，把這個文號從「未處理」改成「已處理」（見第二節），此時應該已經自動離開回到主辦公文清單。
4. 開啟下一件公文，從第二節的清單接續處理，直到清單上所有公文都變成「已處理」為止。
5. 每件處理完可簡短回報進度（文號＋分類＋擬辦一句話），但**不等待回覆**，直接繼續下一件。

## 八、全部完成後：總表回報

1. 對照第二節建立的完整文號清單，確認每一個文號都已標記為「已處理」，沒有遺漏。
2. 向使用者提交一份總表，每件列出：文號、主旨摘要、分類判斷與原因、擬辦文字、設定的流程（會辦誰→陳核誰）、目前狀態（已核章／擬辦已存但未核章／尚未處理等），**並特別標註處理過程中沒把握的判斷**（如會辦人選不確定）。
3. 使用者將依此逐件進系統做最終檢查並親手按「送出」（對外發文的送出，在核章關卡完成之後、系統其他地方的真正發文流程，不是本 skill 操作過程中出現的按鈕）。

## 安全與確認原則

- 絕不代打密碼／PIN碼。
- 全程不中斷詢問：分類、擬辦、會辦人選都自行判斷；不確定之處在最後總表註記，交由使用者最終把關修正。
- **核章（點簽核意見面板裡的 `#btnSignSave`）是每件公文的必要標準步驟，直接做，不用每件都另外詢問確認。**
- **一律不代替使用者執行最終對外發文的送出**——這是保留給使用者親自到系統執行的步驟。日常操作流程（核章→離開→是否存檔並離開→是）本身不會觸發這個對外發文動作，只要照第六、七節的正確順序操作即可安全完成核章並離開。
- 回報處理進度或總表時，只回報**實際核對過、確認存在**的結果（例如簽核表格真的出現承辦紀錄），不可憑記憶或假設回報「已完成」。
- 不需在處理前逐件預先讀取檢查——直接依清單標記未處理、逐件處理、完成才改已處理，避免浪費時間重複讀取。
- 不需寫入 Notion。
- 使用者的更正要複誦確認，並提醒可更新本 skill。
